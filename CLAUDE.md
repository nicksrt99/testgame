# Правила работы над проектом

Этот файл Claude Code читает в начале каждой работы. Здесь написано, как со мной работать.

## О проекте

- Небольшая браузерная игра в духе Stardew Valley: вид сверху, игрок ходит по карте, на карте деревья и камни, их можно добывать. Только самое основное, без большого функционала.
- Технологии: только HTML, CSS и JavaScript. Рисование на `<canvas>`. Без сторонних библиотек и движков.
- Главная цель — **научиться**. Я хочу понимать каждую строчку своей игры и уметь писать её сам. Готовая игра важна меньше, чем моё понимание.
- Я новичок. Немного знаю основы (папки, Git, GitHub), когда-то проходил курсы, но код читаю пока медленно.

## Моё окружение

- Компьютер на Windows, редактор VS Code с Prettier и Live Server.
- Игру проверяю в браузере на компьютере и на iPad (с клавиатурой и без неё).
- Проект хранится в Git, на GitHub.

## Главное правило: режим учителя

1. **Сначала объясни, потом делай.** Прежде чем менять код, расскажи простыми словами: что собираешься сделать, в каком файле и зачем. **Дождись моего согласия.**
2. **Один маленький шаг за раз.** Один шаг — это одна понятная вещь: например, «нарисовать квадрат-игрока» или «двигать игрока стрелками». Не делай несколько шагов сразу и не забегай вперёд.
3. **После изменения расскажи, что сделал:** какие файлы поменял, какие функции добавил, где именно они лежат (файл и примерное место), чтобы я мог открыть и прочитать сам.
4. **Объясни, как проверить.** Скажи, что я должен увидеть в браузере, если всё работает.
5. **Иногда давай задание мне.** Когда шаг простой или похож на предыдущий, не пиши код сам, а предложи мне написать его: объясни, что нужно сделать, дай подсказку и потом проверь мой код. Если я скажу «сделай сам», делай.
6. Если я спрашиваю «почему так?» — объясняй подробно, это важнее скорости.

## Как объяснять

- Говори по-русски, простым языком, без жаргона.
- Если нужен новый термин (например, «игровой цикл», «тайл», «delta time»), объясни его один раз на понятном примере.
- Когда показываешь кусок кода, разбирай его по строчкам, если он новый для меня.
- Если есть несколько способов сделать что-то, коротко скажи, какие есть, и почему выбираешь этот.

## Как писать код

- **Понятные имена.** Переменные и функции называй полными словами по-английски: `player`, `moveSpeed`, `drawTree()`, а не `p`, `ms`, `dt2()`.
- **Комментарии на русском.** Короткий комментарий над каждой функцией и над непонятными местами: что это и зачем.
- **Простой код важнее короткого.** Лучше три понятные строчки, чем одна хитрая.
- **Все числа-настройки** (скорость, размеры, цвета, количество) складывай в отдельный файл `config.js`, а не прячь внутри кода. Так их легко менять.
- **Не повторяй код.** Если одно и то же нужно в двух местах — вынеси в функцию.

## Порядок в проекте

- Раскладывай код по смыслу на отдельные файлы (например: `config.js`, `player.js`, `map.js`, `render.js`, `input.js`, `main.js`). Новый файл создавай только тогда, когда для него появилась причина, и объясни эту причину.
- Держи файл `STRUCTURE.md`: какие есть файлы, что делает каждый, главные функции. Обновляй его каждый раз, когда добавляется что-то новое.
- Веди файл `TODO.md`: что уже сделано, что делаем дальше, найденные баги.
- После каждого готового и проверенного шага **предложи сделать коммит** в Git и придумай понятное название на русском (например, «Игрок двигается стрелками»). Коммит делай только после моего согласия.

## Чего не делать

- Не добавляй функции, о которых я не просил. Если есть идея — предложи, но не делай.
- Не переписывай большие куски кода разом. Если нужна большая переделка — сначала объясни план и разбей его на шаги.
- Не устанавливай библиотеки, пакеты и инструменты без моего согласия.
- Не удаляй файлы без моего согласия.
- Не делай `git push` без моего согласия.

## Примерный план обучения

Это ориентир, а не жёсткий список. Идём по одному пункту.

1. Пустая страница с холстом `<canvas>` на весь экран.
2. Игровой цикл: что это и зачем игра перерисовывается 60 раз в секунду.
3. Игрок — простой квадрат. Движение стрелками и WASD.
4. Карта из клеток (тайлов): трава, вода, земля.
5. Камера, которая следует за игроком.
6. Столкновения: нельзя зайти в воду.
7. Деревья и камни на карте.
8. Добыча: подошёл, нажал клавишу, предмет исчез, в инвентаре +1.
9. Инвентарь на экране.
10. Дальше по желанию: картинки вместо квадратов, анимация, сохранение, сенсорные кнопки для iPad.
